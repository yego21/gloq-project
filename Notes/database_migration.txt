        <h2 id="problem"><span class="emoji">🔴</span>The Problem We Solved</h2>

        <h3><span class="badge badge-problem">ISSUE 1</span>Emoji Encoding Error</h3>
        <div class="error-box">
            <strong>Error Message:</strong><br>
            <code>CommandError: Unable to serialize database: 'charmap' codec can't encode character '\U0001f31e' in position 1</code>
        </div>

        <p><strong>Cause:</strong> Django's standard <span class="inline-code">dumpdata</span> uses ASCII encoding by default, which can't handle emoji characters (🌞🌙) stored in the database.</p>

        <p><strong>Why we have emojis:</strong></p>
        <ul>
            <li>Moon phase indicators in journal entries (🌑🌒🌓🌔🌕🌖🌗🌘)</li>
            <li>User profile data</li>
            <li>Mystical/astrology features</li>
        </ul>

        <h3><span class="badge badge-problem">ISSUE 2</span>ContentType Conflicts</h3>
        <div class="error-box">
            <strong>Error Message:</strong><br>
            <code>django.db.utils.IntegrityError: duplicate key value violates unique constraint "django_content_type_app_label_model_76bd3d3b_uniq"</code>
        </div>

        <p><strong>Cause:</strong> Loading fixtures into a database that already has ContentType records causes unique constraint violations.</p>

        <h3><span class="badge badge-problem">ISSUE 3</span>Signal Interference</h3>
        <p>User profile signals (like auto-creating profiles on user creation) fire during fixture load, causing duplicates or unwanted side effects.</p>

        <h3>The Script: db_dump.py</h3>

        <pre><code># db_dump.py
import os
import sys
import json
import django
import environ
from pathlib import Path

# Setup environment exactly like manage.py does
BASE_DIR = Path(__file__).resolve().parent.parent
env = environ.Env()
environ.Env.read_env(BASE_DIR / '.env')

django_env = env('DJANGO_ENV', default='dev')
print(f'django env:{django_env}')

# Set settings module based on environment
os.environ.setdefault('DJANGO_SETTINGS_MODULE', f'gloq.settings.{django_env}')
django.setup()

from django.core import serializers
from django.apps import apps
from django.conf import settings

print("🌙 Starting UTF-8 database dump...")
print(f"📂 Settings module: {settings.SETTINGS_MODULE}")

# Get database info
try:
    db_config = settings.DATABASES.get('default', list(settings.DATABASES.values())[0])
    db_name = db_config.get('NAME', 'Unknown')
    print(f"📊 Database: {db_name}")
except Exception as e:
    print(f"📊 Database: Could not read config ({e})")
print()

# Get all models, excluding problematic system tables
print("🗂️  Loading models...")
excluded_models = ['contenttypes.contenttype', 'auth.permission']
all_models = [
    model for model in apps.get_models()
    if f"{model._meta.app_label}.{model._meta.model_name}" not in excluded_models
]

print(f"Found {len(all_models)} models (excluding system tables)")
print()

# Count and collect objects
print("🔍 Collecting data:")
all_objects = []
model_stats = {}

for model in all_models:
    try:
        count = model.objects.count()
        model_name = f"{model._meta.app_label}.{model._meta.model_name}"
        model_stats[model_name] = count
        
        if count > 0:
            print(f"  ✓ {model_name}: {count} objects")
            objects = list(model.objects.all())
            all_objects.extend(objects)
        else:
            print(f"  ○ {model_name}: 0 objects (skipping)")
    except Exception as e:
        print(f"  ✗ Error: {e}")

print()
print(f"📦 Total objects to serialize: {len(all_objects)}")

if len(all_objects) == 0:
    print("⚠️  WARNING: No objects found!")
    sys.exit(1)

# Serialize with UTF-8 support
print("📝 Serializing data...")
data_json = serializers.serialize('json', all_objects, indent=4)

# Parse and re-dump with ensure_ascii=False (preserves emojis!)
data = json.loads(data_json)

# Write with UTF-8 encoding
output_file = f'db_dump_{django_env}.json'
print(f"💾 Writing to {output_file}...")
with open(output_file, 'w', encoding='utf-8') as f:
    json.dump(data, f, indent=4, ensure_ascii=False)

print()
print(f"✅ Successfully dumped {len(data)} objects!")
print()
print("🌞 Emojis preserved: 🌑 🌒 🌓 🌔 🌕 🌖 🌗 🌘")</code></pre>

        <h3>Safe Load (With Signal Control)</h3>
        <p>For loading with signal management, create a custom command.</p>

        <p><strong>File:</strong> <span class="inline-code">userprofile/management/commands/loaddata_safe.py</span></p>

        <pre><code>from django.core.management.base import BaseCommand
from django.core.management import call_command
from django.contrib.contenttypes.models import ContentType

class Command(BaseCommand):
    help = 'Safely load fixture data with signal control'

    def add_arguments(self, parser):
        parser.add_argument('fixture', type=str, help='Fixture file')
        parser.add_argument('--fresh', action='store_true', help='Fresh load')

    def handle(self, *args, **options):
        fixture = options['fixture']
        fresh = options.get('fresh', False)

        self.stdout.write('🔧 Starting safe fixture load...')

        # Disable signals
        signals_disabled = False
        try:
            from userprofile.signals import disable_signals
            disable_signals()
            signals_disabled = True
        except ImportError:
            pass

        try:
            if fresh:
                ContentType.objects.all().delete()

            # Load fixture
            call_command('loaddata', fixture, verbosity=2)
            self.stdout.write('✅ Fixture loaded!')

        finally:
            # Re-enable signals
            if signals_disabled:
                try:
                    from userprofile.signals import enable_signals
                    enable_signals()
                except ImportError:
                    pass

        self.stdout.write('🎉 Done!')</code></pre>

        <h2 id="signals"><span class="emoji">🔔</span>Signal Management</h2>

        <h3>Why Signals Are a Problem</h3>
        <p>When loading fixtures, Django creates model instances. If you have signals that auto-create related objects, they fire during fixture load, creating duplicates!</p>

        <div class="warning-box">
            <strong>Example Problem:</strong> A <span class="inline-code">post_save</span> signal that creates a UserProfile when a User is created will fire during fixture load, even though the UserProfile is already in the fixture!
        </div>

        <h3>Signal Control Implementation</h3>
        <p><strong>File:</strong> <span class="inline-code">userprofile/signals.py</span></p>

        <pre><code>from django.db.models.signals import post_save
from django.dispatch import receiver
from django.contrib.auth.models import User

# Global flag to control signals
_signals_enabled = True

def disable_signals():
    """Disable all signals in this module"""
    global _signals_enabled
    _signals_enabled = False

def enable_signals():
    """Re-enable all signals in this module"""
    global _signals_enabled
    _signals_enabled = True

@receiver(post_save, sender=User)
def create_user_profile(sender, instance, created, **kwargs):
    # Check if signals are enabled
    if not _signals_enabled:
        return
    
    if created:
        from .models import UserProfile
        UserProfile.objects.get_or_create(user=instance)</code></pre>

        <h2 id="troubleshooting"><span class="emoji">🔧</span>Common Issues & Solutions</h2>

        <h3>Issue: "charmap codec can't encode character"</h3>
        <div class="error-box">
            <strong>Problem:</strong> Windows console can't display/write emojis
        </div>
        <div class="success-box">
            <strong>Solution:</strong> Use the custom <span class="inline-code">db_dump.py</span> script which forces UTF-8 encoding
        </div>

        <h3>Issue: ContentType already exists</h3>
        <div class="error-box">
            <strong>Problem:</strong> Loading into database that already has ContentTypes
        </div>
        <div class="success-box">
            <strong>Solutions:</strong>
            <ol>
                <li>Use <span class="inline-code">--fresh</span> flag with <span class="inline-code">loaddata_safe</span></li>
                <li>Clear ContentTypes manually before loading</li>
                <li>Exclude ContentTypes from dump (already done in script)</li>
            </ol>
        </div>

        <h3>Issue: Duplicate user profiles after load</h3>
        <div class="error-box">
            <strong>Problem:</strong> Signals firing during fixture load
        </div>
        <div class="success-box">
            <strong>Solution:</strong> Use <span class="inline-code">loaddata_safe</span> command with signal control
        </div>

        <h3>Issue: Wrong database being dumped</h3>
        <div class="error-box">
            <strong>Problem:</strong> Multiple environments (dev/prod)
        </div>
        <div class="success-box">
            <strong>Solution:</strong> Check your <span class="inline-code">.env</span> file - make sure <span class="inline-code">DJANGO_ENV</span> is set correctly
        </div>

        <h3>Issue: Empty dump (0 objects)</h3>
        <div class="error-box">
            <strong>Possible causes:</strong>
            <ul>
                <li>Wrong DJANGO_ENV setting</li>
                <li>Database file doesn't exist at expected location</li>
                <li>Models not properly registered</li>
            </ul>
        </div>
        <div class="success-box">
            <strong>Debug:</strong><br>
            <code>python manage.py shell</code><br>
            <code>>>> from journal.models import JournalEntry</code><br>
            <code>>>> JournalEntry.objects.count()  # Should show number > 0</code>
        </div>
